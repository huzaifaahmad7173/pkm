# Knowledge & Documentation Agents Guide

Rules for authoring and maintaining project documentation. Source of truth: the docs in this folder (`how-to-guides.md`, `glossary.md`, `troubleshooting.md`).

## How-To Guides (`how-to-guides.md`)

- Write practical, step-by-step guides for development, deployment, onboarding, and operations.
- Use a consistent template for every guide:
  - **Purpose** — what the guide accomplishes
  - **Prerequisites** — what's needed before starting
  - **Steps** — numbered, sequential instructions
  - **Verification** — how to confirm success
  - **Troubleshooting** — common issues and fixes
- Keep guides concise and accurate; update them whenever the process changes.

## Glossary (`glossary.md`)

- Maintain a shared vocabulary for technical, business, and project-specific terms.
- Keep definitions short and easy to understand.
- Add new terms when introducing new concepts; use consistent terminology throughout the project.
- Update the glossary as the project evolves.

## Troubleshooting (`troubleshooting.md`)

- Document every issue with a consistent structure:
  - **Issue** — describe the problem
  - **Possible Causes** — bullet list
  - **Resolution** — numbered steps
  - **Prevention** — tips to avoid recurrence
- Identify and explain the root cause before applying a fix.
- Record issues as they are discovered and update solutions when the project changes.

## General Rules

- Follow the project's frontmatter convention for docs: `title`, `description`, `tags`, `status` (and `related` where relevant).
- Keep documentation accurate, up to date, and consistent across all folders.
